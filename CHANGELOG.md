# Changelog

All notable changes to Action Stations are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses
[Semantic Versioning](https://semver.org/). Pull requests are referenced as `PR #NN`, issues
as `#NN`. Releasing: rename `[Unreleased]` to the new version with the release date, then run
`scripts/release.sh` (see `docs/RELEASING.md`).

## [Unreleased]

## [0.6.1] - 2026-10-30

### Added

- The self-hosted server image on GHCR is published for ARM (arm64) as well as x86-64 (amd64), so it runs natively on AWS Graviton, Raspberry Pi 4 or 5 and other ARM hosts (#547).

## [0.6.0] - 2026-10-30

### Changed

- The Action Stations relay runs on Cloudflare Workers Paid, with larger caps (#539, ADR-0066): 100 sessions a day across everyone and 10 per address (were 25 and 3), and per session 15,000 row writes, 7,500 stored messages and 24 MiB stored (were 3,600, 1,500 and 12 MiB), so larger exercises and more organizations fit on one day. The caps keep the worst month inside the plan's included allowance. Using the relay still costs users nothing.

### Added

- Self-hosted server on Windows (#509). Tested the win-x64 executable on Windows 11: the startup task, firewall rule, health, session creation and WebSocket join all work from another machine, and `service uninstall` removes them. Fixed: `service install` failed with ENOENT when the data directory did not exist yet. New `relay/node/scripts/smoke.mjs` checks a running server; the release workflow's `relay-image` job publishes the GHCR image on a tag push.
- Redline export checked in Word, LibreOffice and Pages (#504); results are in `docs/guides/redlines.md`.
- Weekly stats reminder (#381): `pnpm stats:reminder install` adds a macOS notification every Monday at 09:00 to run `pnpm stats` and open a `chore(stats)` pull request.
- Locations pages for geographic maps (#500, spec 0436 FR-8). The MSEL and controller handbook now include a Locations page for each geographic map the MSEL uses: the places plotted by latitude and longitude on a plain frame, numbered, with a legend that gives each place's rows and coordinates. There is no street map on these pages, and the page says so.
- Place labels on offline maps (#500, spec 0436 FR-17). The offline styles now name places, roads and water in vector maps, using Noto Sans (Latin ranges, SIL Open Font License) bundled in the app, so labels need no network.
- Tile pyramid for large site plans (#500, spec 0436). A plan over 2048 pixels is cut into 512 px tiles (built on first use and after import, kept in `.cache/maps/`), and the plan view draws only the tiles in view at the right detail, so an 8000 x 6000 plan pans and zooms smoothly.
- Map on devices (#500, spec 0436 FR-8). While a live session runs, the Facilitate Map tab has a "Map on devices" checkbox. Each phone gets the map with only the places of messages that reached its seat, in a frame addressed to that device alone (`map.state`). Site plans arrive as a sealed picture; geographic maps show a schematic with coordinates. The player page stays under its size budget.
- LIVE tests and example regeneration with a local model (#514, part of #499, part of #503). `LIVE=1 pnpm test src/main/generate/aar-sitman.live.test.ts` runs the `aar`, `sitman` and `eeg` stages against LM Studio. With qwen3-30b-a3b-2507 the first runs showed that `sitman` wrote modules for phases that do not exist and `eeg` wrote more guides than it could finish and listed only the first objective, so replies were cut off. The prompts now state the counts, the schemas cap modules (8), guides (6) and tasks (3 to 6), and the `eeg` call forces one `objectiveCapabilities` entry per objective, keeps the mapping to six capabilities and writes any guide the first reply left out in its own call (the model used to write one guide and stop); new lints `EEG_COLLAPSED` and `EEG_GUIDE_MISSING` flag one guide for more than two objectives and a mapped capability with no guide; an objective copied back as the whole "name: text" line is matched. `make-example.mjs stages` adds the guides and the Situation Manual to an already packaged example without regenerating it, and the bundled examples now carry both for all 22 scenarios. The first published benchmark run (standard suite, qwen3-30b-a3b-2507, overall 59.9) is in `docs/benchmarks/runs/`; its judge scores are marked unpublished until the maintainer's calibration rows exist. The determinism check found that two repeats at one seed differ on LM Studio.
- Model benchmark follow-ups (part of #503): `pnpm bench -- --judge lmstudio:<model>` adds the optional local plausibility judge (local only, quoted evidence required, publishable only with enough human-scored calibration rows, never in the overall score) and `--determinism` runs two repeats at one seed and reports whether they match. Not done: the first published runs of the setup-tier models, which need strong models and long runs on the maintainer's hardware.
- Program, redlines and health follow-ups (part of #504): the Headings tab shows how many proposed changes sit at or under each heading; a redline card shows the latest regression drill verdict; **Import CSV…** on the program's Actions page reads an existing corrective-action list (validated row by row, formula-safe, duplicates skipped); program snapshots list plan headings to depth 3 from the whole index rather than the first 60 of the ingest preview. Not done: the manual Word, LibreOffice and Pages check of tracked changes (#431), which needs those applications and stays in the guide as a hand check before changing the export code.

New frames `partner.receipt`, `simcell.draft`, `simcell.action`; roster `permissions`; servers refuse host-only frames from a co-controller's connection and its HTTP actions. See ADR-0064.

Every step, the MSEL repair and the critique revision leave partner rows as their owner wrote them (they are still read as context), and the MSEL editor marks them **Owned by** their organization and keeps them read-only.
- Live play follow-ups (part of #494): **Resume** on an interrupted LAN session reopens it on the same address and port from the keys kept in the keychain and continues its log; the Live tab lists devices with **Remove** and **Replace keys** (new key epoch, old links stop working); Facilitate publishes `clock.state` to devices and sends tracker prompts to evaluator devices as `controller.notice`; device receipts, messages and closed votes feed the tracker's not-opened and answered rules and the commitment suggestions; branch decisions are appended to the session log. See the [live play guide](docs/guides/live-play.md).
- Evaluation and AAR follow-ups (#498). The MSEL grid has a read-only **Criteria** column (toolbar button **Criteria column**) and a "Criteria: T-01, T-04" line under the expected action of rows that evaluation guides link to; the EEG packet export can print one blank copy per evaluator seat (**Copies of the evaluation guides** on Export, labelled Evaluator 1, Evaluator 2 and so on); an evaluator can edit a general observation after saving it (same observation, next revision); program snapshots count live-log observations as well as `evaluation.json`; the AAR/IP draft receives the tracker report, regulatory clock results and marked hot wash quotes as cited evidence (`trk:`, `clk:`, `tr:`), and the Draft dialog warns, naming the provider, when those quotes would go to a cloud model.
- Live play follow-ups, part 2 (part of #494): sessions on the relay or your own server can be resumed after a restart when the server still holds them; **Show on screen** puts a branch decision on the presentation screen; an inject can be sent to one chosen player device; the Room counts **Away** devices, sets the unanswered window per session and honours a row's own window; the Facilitate timeline shows **No response** on flagged rows.
- Live play follow-ups, part 3 (closes #494): a past session's hot wash board is rebuilt from its log, and a device keeps its own items' marks across a reload; survey answers lost in a crash are put back from the log; a checklist after ENDEX; the `live_log` export target; a phone inject can ring as a call; the host sends the regional co-controller roster to devices and the Live tab lists it.
- Micro-drills on players' devices (#437, #499, ADR-0065). **Send to devices** on a Ready drill in a running live session: each player gets the situation and questions on their phone, answers alone, and gets the check, prewritten hints or a checklist back on that phone only. New host-only frames `drill.open`, `drill.close`, `drill.feedback` and the player frame `drill.answer`; the Micro-drills screen shows each participant's progress by label and **Close the drill and finish every run** ends it. Regulation triggers in generation (#426, #499): `msel_phase` is told which reporting triggers are switched on and may name one on the row where that moment happens; a row that does not read like the moment loses it, and each kept trigger is noted for you to confirm.
- Generation and content follow-ups (#499, ADR-0063). The Excel MSEL gets a **Plan Seam** column (only when rows test a seam) and the HSEEP Controller/Evaluator Handbook a **Plan Seams This Exercise Tests** section (#427). In the MSEL editor, **Generate branch rows** on a branched decision asks the model for rows for every option, checks them on a copy (branch windows, rejoin rows, branch lints) and shows them for you to apply or discard; rows of a branch are now re-timed between their decision and rejoin rows by the structural repairs, and a branch's own ENDEX is kept. A proposed inject shows its source check and offers **Accept anyway** when it is unsupported (#430). Each MSEL row has a **Controls** dialog: accepted controls, dashed suggestions from the framework rules (also stored on rows when a phase is generated) to accept or dismiss, a searchable picker, and, only when **Settings, Compliance, Let the model suggest controls** is switched on, **Suggest controls** with the routed review model; the Word handbook and the HSEEP handbook (Appendix F) get a Compliance coverage section (#426). **Micro-drills** can be made from a scenario (one draft per plan section it tests, up to five), and a drill run on a section an action cites can be chosen as evidence when verifying a corrective action (#437). Not done: regenerating the bundled examples and the live player page for drills.
- Regional exercises (#440, ADR-0062): several organizations plan one exercise while each keeps its plans on its own computer. The new **Regional** screen creates organization identities (a signing key kept in the OS keychain), exports a frame, a slice or the merged exercise as a signed `.asexercise` file after a review of exactly what leaves, pins each partner's key after you type the fingerprint they read to you, and lets the host merge slices with a field-level diff and conflict warnings. Rows are owned by an organization, a row can be private to its controllers (partners see a placeholder), and changes to a partner's row are proposals. The joint live session roster and per-organization log slices are built from the pinned keys. See the [regional exercises guide](docs/guides/regional-exercises.md) and the [bundle format](docs/exercise-bundle-format.md).
- Community pack credit (#441): `pack.json` takes `contributors` (name, link, GitHub user, roles) and `author.github`; catalog entries may carry contributors, endorsements and review dates. Browse, the review screen and Installed show the credit, an Official or Community label (derived from the id) and endorsement counts as text; search matches contributor names. Older apps ignore the new fields. Export as pack has a contributors editor, and `pack-validate.mjs` lists the author and contributors of each valid pack.
- Maps (#436, ADR-0060). **Maps** in the sidebar holds site plans (PNG, JPEG or WebP) and geographic maps with named places pinned on them, by click or typed coordinates; **Facilitate > Map** shows delivered, due and (on request) upcoming rows at their places, with a Locations list for keyboard and screen reader use. Map data: online maps (OpenFreeMap, OpenStreetMap standard under its tile policy, or a custom address; off until you turn them on in **Settings > Maps**, which says what the provider sees), state map files from the Action Stations maps catalog, small OpenFreeMap areas within its offline limits, and your own `.pmtiles` or `.mbtiles`. Downloads are started by you, resumable and checked by sha256, and attribution is always on the map. New dependencies: `maplibre-gl` and `pmtiles` (BSD-3-Clause). Not yet: PDF pages, the presentation window and devices, export pages, offline place labels. Guide: `docs/guides/maps.md`.
- Optional hazard data (#439, ADR-0061): off by default; with **Settings, Hazard data** on, **Hazard context** fetches NWS alerts and forecast, USGS earthquakes, NASA FIRMS fire detections (free map key in the keychain) and OpenFEMA declarations for the project's rounded location, only when you press Fetch and after the dialog shows each host and what is sent. The result is a dated snapshot in the project, so exercises work offline. Ideas can **use hazard context**, the handbook lists the sources with their attribution, and infrastructure layers are imported from a local file
- Surveys on phones (#422, ADR-0058): **Send to devices** on a survey's Deliver dialog and in the Live tab sends a survey to everyone in a live session, or starts a **survey session** on this computer that shows only a join code, so participants answer on their phones with no accounts. Participants find it under **More, Surveys** (a banner offers it while it is open): rating and confidence scales, single and multiple choice, and free text, each a labelled group with required questions checked before sending, answers kept and sent when the connection returns, and a change allowed until you close the survey. Answers are sealed to the controller and stored with no device, seat or name, so results use the same anonymity threshold as paper responses. Counts show how many devices answered, never who.
- Controller tools in Facilitate (#428, ADR-0059). The exercise clock gets nudge buttons (−5, −1, +1, +5, +15 and the `[` `]` keys), a rate (0.5× to 10× in the menu, up to 60× typed), a clock log, and a dialog when you move back past delivered rows (keep them, or mark them not delivered, which also withdraws them from devices); Reset asks first once rows were delivered. Rows can address a **team** as well as roles, **Deliver to…** (`Shift+D`) changes the recipients for one delivery, and chips above the timeline show the rows for a team or role. A social post can carry an **engagement plan** (counts that surge, climb steadily or fade, and timed replies); after delivery the Inject tab shows the counts and **Refresh on screen** redraws the post with them on the presentation window. The new **Tracker** tab lists injects nobody answered, commitments that came due or have no time, and expected actions nobody recorded; notes are read for promises ("we'll notify the FAA by 10:30") and offered as suggestions, nothing is added without you. Rules only, English; no model is called. Guide: `docs/guides/facilitate.md`.
- Live play: hot wash contributions from devices (#415, ADR-0052). Players and evaluators add strengths, improvements and answers, anonymously if they choose; the facilitator groups, edits, hides and promotes them on a Hot wash board and on the projector, and promoted findings go into the AAR/IP draft.

- Micro-drills (#437, ADR-0057). **Micro-drills** in the sidebar builds a 15-minute drill from one section of one plan (up to about 12,000 tokens): a situation, three to five questions, expected points that each cite a passage in the section, and three prewritten hints per question (Level 1 what to consider, Level 2 which plan section and page, Level 3 the plan line quoted). Checks run on every save (citations inside the section, Level 3 quote word for word, no question that contains its answer, length fits, stray person names) and keep a drill from Ready unless overridden. Run it alone or with two to six people around one screen: answers are checked against the expected points (after three fixed test answers confirm the model judges sensibly, else a checklist you tick), hints are offered after a missed answer and are the drill's own text, never written at run time, and fade on repeat runs by participant label (the rule is shown on screen). The clock counts up, can be paused and never stops the drill. The debrief lists covered and missed points with plan section and page, model answers and a review line, and saves as PDF. Finished runs add totals only (no answers, no names) to the linked program's project snapshot, and **Program > Health** shows **Practised in drills** per plan section, apart from exercises. The screens and guide say the evidence for the format is thin. Not yet: the live player page. Guide: `docs/guides/micro-drills.md`.
- The SimCell assistant with voice calls (#429, ADR-0056). A **Personas** tab in the scenario editor builds cards for the outside parties from the SimCell scripts (optionally filled in by the model, reviewed by you before saving): goals, deadlines, escalation rules, what each knows, does not know and must never reveal, and concessions with conditions. There is no free-text personality field, and the editor refuses names that tie a public office to a name or match a contact in your project. In Facilitate, **SimCell** drafts in-character replies to players' messages and when a persona's deadline or rule comes due; each draft shows the goal, deadline, rule or concession it applied and plain-text checks (a secret revealed, a concession without its condition, agreeing for no reason, breaking character, an unknown person's name, too long), and you **Send**, **Edit and send**, **Regenerate**, **Write my own** or **Discard**. Nothing is ever sent without you, drafts never reach players, and approved replies go out as ordinary controller messages. A new **SimCell replies** task (falls back to **Drafting**) is checked with eight fixed probes: Suited drafts on its own, Limited drafts only on request, Not suited stays off. Without a live session you can type what a player said and get a reply to read aloud or play as voice, saved with the hot wash notes. A persona can ring a role, team or device as a turn-by-turn voice call (`call.ring`, `call.answer`, `call.end`): players hear the line and always see its words, answer by typing or by tapping to talk, and spoken answers are transcribed on the facilitator's computer and deleted afterwards unless you keep them. The player page now may use the microphone, only when a player taps to talk. Export adds `personas.md` to the facilitator folder. Guide: `docs/guides/live-simcell.md`.
- The Room and the session log (#417). A new **Room** tab in Facilitate shows, for the running session or any past one, who is connected per seat (empty player seats are flagged), each released inject with delivered, read and acted-on counts, time to first read and the response, an **Unanswered injects** list (a release that expects a response and has had none after 10 minutes; an acted-on receipt, a later message from a targeted seat, or **Mark answered** clears it, and each new one is announced once to screen readers), messages waiting and median reply time, votes, hot wash and evaluation counts, and the health of the session (dropped frames by reason, log size). The **Log** view lists the newest 200 entries with a kind filter and search, **Load earlier** and **Star**. The Live tab lists past and interrupted sessions with **View**, **Export JSON**, **Export CSV** (UTF-8 with a byte order mark, formula-safe, display names only for a named session when you tick **Include display names**), **Close as ended** and **Delete session data**. `readSlice` is the one way other features read the log; the after-action report's live-log reader now uses it.
- Evaluator observation forms (#416, ADR-0054). An evaluator opens the staff link, takes the Evaluator seat and gets, under **More > Evaluate**, the exercise's critical tasks grouped by Core Capability with the plan citation, the role expected to do each, the timing and the MSEL rows where to look. Each task is rated met, partial, not met or not observed (a word and an icon, never colour alone), with a note, the exercise time and the linked inject. A **Watch for** strip lists the tasks an inject should trigger when it is released; filters show **My watch list**, **All tasks**, **Unrated** or **Due now**; **Add an observation not tied to a task** records strengths and gaps the guides did not expect. Ratings are kept on the device and queued while it is offline, then sent once and in order. Observations reach the session log (every revision) and `evaluation.json` (latest revision, `source: 'live'`), where the Evaluation tab, the hot wash and the AAR read them. In the Live tab you set each evaluator's watch list and whether expected actions are shown; the Evaluation tab gains a coverage matrix, the latest observations with filters and **Ask to watch**. Only devices on the staff link receive the assignment. The AAR no longer counts a live observation twice when both the log and `evaluation.json` hold it. Fix: a phone's queued actions (receipts, messages, observations) are now sent when catch-up finishes, not only at the welcome.
- Spanish player material and accessible packets (#435, ADR-0055). The scenario's **Languages** tab switches Spanish (US) on for the Player Briefing Packet, the Player Handouts and the injects players see (controller-only rows are skipped; controller material only when you ask). **Translate** runs through the text model routed to the new **Translation** task (the drafting model when unset), naming it, and saying so when it is a cloud one, before it runs. Each item is reviewed side by side (English read-only, Spanish editable, both marked with their language) and is Needs review, Reviewed or English changed; a glossary (default EXERCISE to EJERCICIO) is applied and checked. Fields the template marks `x-translate: false`, or that have an `enum`, `pattern`, `format` or a `maxLength` of 8 or less, stay as written. **Export refuses unreviewed Spanish** and lists the items; **Export unreviewed translation** stamps every page "Traducción automática sin revisar / Unreviewed machine translation". The Export screen's **Player material** chooses English, Spanish or both and **Also write a large-print copy**; Spanish files go to `players/es/` of the ZIP (and `facilitator/es/` for the handbook if asked), with `-es` and `-large-print` in their names. Templates gain `labels/<lang>.json` and a `t` helper, and the first player-facing templates ship `labels/es.json`. New: **Player injects** export (a card per inject, picture then its words as text), tagged inject media PDFs, a short `alt` plus the words as real text after every deck picture, `lang` and a title on every exported document, and a large-print layer (18 point, one column, sans-serif). Guide: `docs/guides/translation-and-accessibility.md`.
- Branching scenarios decided by rules (#430, ADR-0049). A decision-point row can fork the MSEL into two to six labelled branches that rejoin the main line or end the exercise. **Branches** in the MSEL editor makes a decision from a decision-point row (**Branch this decision…**) and sets, for each decision, its rule (most votes, majority, threshold for one option, unanimous, controller decides), default option, timeout and each branch's rejoin row; branch rows carry a left bar and a "Branch B1: Pay" label in text, **Show path** dims everything off the trunk, one branch or the default path, and rows can be moved to a branch, a branch converted to trunk or deleted with its rows. New checks: `BRANCH_UNREACHABLE`, `BRANCH_DEAD_END`, `BRANCH_REJOIN_BACKWARD`, `BRANCH_CYCLE`, `BRANCH_EMPTY`, `BRANCH_ROLE_GAP`, `BRANCH_TIME_ORDER`, `BRANCH_DEPTH`, `DECISION_NO_DEFAULT`, `DECISION_OPTION_ORPHAN`, `DECISION_NOT_DECISION_POINT`. In Facilitate a **Decisions** tab closes the open decision: type a show of hands and **Decide by rule**, or let the controller choose; override a decision (with a required note) until the first row of the chosen branch is delivered. Only rows on the path the decisions lead to can be delivered, the others show "Not taken". The option is always computed from the tally and the rule or picked by a person, never by a model; **Propose next inject** asks the model for one more row in a thin branch, shown in a review card you accept or reject. Every step goes to a local log (`scenarios/<id>/live/local/log.jsonl`) and **Replay check** replays it against the scenario and compares it with the hash written when the state last changed. Exports: the MSEL PDF prints each branch as a shaded sub-table after the phase of its decision; the MSEL workbook gets a Branch column, a sheet per branch and a Decisions sheet; **MSEL of one path** prints the path played (with the decisions taken) or the default path (with the alternatives); `scenario.md` lists decisions and branches. A scenario with branches is saved as format 2, which older builds refuse to open; scenarios without branches are written as before.
- Decision-point voting (#414, ADR-0050). Put a decision to the room: open a vote from an MSEL row that has a decision (the one the branching editor sets) or from the new **Votes** tab; a branch decision's tally feeds its rule, and players answer in one tap on their phones and can change their mind until it closes. **Show on screen** puts the bars, counts and "N of M voted" on the presentation window; **Close** (or a countdown) freezes the tally and devices show the result; **Reopen** works for two minutes; **Record as decision** adds "Shut down now (7 of 12), vote at 2:14" to the decision log for the hot wash and the AAR. Votes are anonymous by default: the log has the tally and one line per ballot with the option and time, no device and no role. **By role** splits the result by role but shows any role with fewer devices than the group size (3 by default, never under 2) as Other, in the display and in the log, and warns before it opens. Optional anonymous reasons, live results on devices, targeting by role or team. Guide: `docs/guides/live-play.md`.
- Choose the live play connection per exercise (#410, ADR-0051). The Live tab offers **This computer**, **Action Stations relay** and **Your server**, each with a plain statement of what it sends where, a **Test connection** checklist, and, for the relay and a server, a confirmation the first time an exercise uses it (nothing contacts a server before that and before Test or Start). A server with its own certificate shows its fingerprint to confirm; the app then accepts only that certificate and stops if it changes. Server keys are stored encrypted on this computer; **Settings > Live play** lists remembered servers and the default connection. The relay is not deployed yet.
- Program health dashboard (#438). **Program > Health** shows, from the program's own snapshots and corrective actions (no project folder is opened), which of the 32 Core Capabilities have been exercised by quarter of the cycle with last date, observation counts and open actions, and a status of Current, Stale (before the cycle or more than 24 months ago, adjustable), Planned only or Never exercised; which plan sections to three levels exercises have cited and which never have, matched across projects by heading; corrective actions by status, ageing, organization and overdue list; and a never-tested list and timeline. Filters (project, year, mission area, plan document) are kept in the address so a view can be bookmarked. Every panel is a sortable table; the one chart has a hidden table with the same numbers. A capability count opens the exercises behind it, with a link to the corrective actions for that capability. Export a dated PDF and a ZIP of the CSV tables behind it, with an option to leave out owner names. Guide: `docs/guides/program.md`.
- Real-world alert formats and exports for other platforms (#432, ADR-0046). New inject templates `cap_alert` (IPAWS-style review screen and CAP 1.2 XML) and `eas_broadcast` (TV crawl and decoder log); `notam` gains an ICAO variant, `nws_weather_warning` covers statements, Special Weather Statements and watches, and `notam`, `nws_weather_warning` and `ics_213_general_message` move to template version 2. The SAME header, VTEC and UGC lines and CAP times are built by the app, never by the model, and every alert is marked as an exercise. New export targets under **For other platforms**: a Conducttr MEL CSV, a WebEOC / SimulationDeck package (format unverified) and CAP XML files, kept out of the players' ZIP folder. See the [platforms guide](docs/guides/eoc-platforms.md).
- Messages with the SimCell (#413, ADR-0045). Players write to the SimCell from their phone, with up to three photos, optionally replying to an inject; the facilitator answers in character from the new **Messages** tab (threads per role, personas from the scenario's SimCell scripts, one-tap script replies, "played by SimCell" on by default, mark handled, star, pin to hot wash, start a thread with a role, team or device). Every message is logged with the role and exercise time.
- Plan redlines and regression drills (#431, ADR-0048). **Propose plan redlines** in the after-action report drafts revised wording for the plan sections its areas for improvement cite: each proposal quotes the current text word for word (a quote that is not in the section is sent back once, then dropped), gives new wording and a two-sentence reason, and carries the source check label. **Redlines** in the sidebar shows each as a word diff with deleted and inserted words named in text, lets you edit, accept or reject it, and exports the accepted ones: a copy of a Word plan with real tracked changes (only the changed words, author "Action Stations", formatting kept), or a change memo (Word, and PDF if you tick it) quoting the current and proposed text for PDFs and other plans and for anything in a table or text box. #### Generation and checks

- Checks and prompt rules for the defects found while building the 0.4.0 examples (#347). The `msel_phase`, `inject_text`, `objectives_roles`, `scenario_overview` and `critique` prompts state the same rules, and `msel_phase` now receives the designer's request and constraints as binding for start time, day, places and threat.
