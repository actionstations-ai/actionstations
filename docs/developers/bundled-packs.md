# Included packs and reference libraries: how they are built

Maintainer notes for the packs the app ships and the reference libraries in the official catalog. The pack format itself is in [Pack and catalog formats](../packs-format.md). This page is not published on the docs site.

## Included packs

`node scripts/build-bundled-packs.mjs` (part of every build) builds the included packs from the repository folders. An unpackaged run (dev, unit tests, e2e) reads `packs/bundled.json` (compiled in) over the repo folders in place, so editing a template shows at once; `TTX_BUNDLED_PACKS=<folder>` makes it read a built folder instead. A packaged build reads `app-resources/packs/`.

### packs/bundled.json

Maps the repo's folders to packs (schema `BundledMap`). Top level: `author`, `license` (`LicenseRef-Action-Stations`: the app's terms), `homepage`, `packs[]`. Per pack:

| Field         | Rules                                                                                                                               |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `id`          | `ai.actionstations.<name>`; the documents folder is `<name>`                                                                        |
| `name`        | shown on the Packs screen and in the **Included: <name>** badge                                                                     |
| `summary`     | one line; `description` optional                                                                                                    |
| `core`        | `true` for exactly one pack: always enabled, cannot be disabled                                                                     |
| `domains`     | domain ids the pack is for (scopes its prompts); empty for the core                                                                 |
| `tags`        | as in `pack.json`                                                                                                                   |
| `contents`    | `templates`, `prompts`, `domains`, `workflows` (core only), `examples`: ids of items in the repo folders below                      |
| `documents[]` | `path` (`<slug>/<file>`), `title`, `license` (`LicenseRef-US-Government-Work` or `CC0-1.0` only), `publisher`, `url`, `description` |

Where items come from: `templates/injects/<type>/` (without `__golden__/`), `prompts/<name>.md`, `comfy/workflows/<id>.json` + `<id>.bindings.json`, `packs/domains/<id>.json`, `examples/<slug>/` (without `index.sqlite*`, `.cache/` and dotfiles other than `project/.gitignore`), and `packs/documents/<name>/<slug>/<file>`. A document's `pack.json` entry gets `source` = `<publisher>, <url>`. `packs/readmes/<name>.md`, when present, ships as the pack's root `README.md` (the domain packs name their required plans, reporting deadlines and the copyrighted references they do not bundle there). Version and `minAppVersion` are the app's version.

### Build

`node scripts/build-bundled-packs.mjs` (run as part of every build) assembles every pack, hashes every file, and validates each pack with `readPack` as an in-memory archive (`trusted`: a bundled pack may provide the built-in domain ids). It fails, writing nothing, when an item in the repo is mapped to no pack or to two, a mapped item is missing, a domain pack lists workflows, a document file has no `documents[]` entry, a `packs/readmes/<name>.md` names no pack, the documents of all packs exceed 60 MB, or the reader refuses a pack. The same mapping check also runs in the project's automated tests. Output:

```
out/bundled-packs/                 → app-resources/packs/ in a release (electron-builder.yml)
  index.json                       { formatVersion: 1, appVersion, packs: [{ id, core, items }] } (map order)
  <id>/pack.json                   full manifest: files[] with sha256 and size
  <id>/templates/… prompts/… …     the pack's files
```

`app-resources/templates/_shared` (fonts and CSS every template uses) and `app-resources/templates/export` (export page templates) still ship beside it: they are not pack items.

## Reference libraries

Reference documents are pinned in `packs/documents/manifest.json` (schema `DocumentsManifest`). The core pack carries the cross-sector set (HSEEP doctrine and templates, NIMS, CPG 101, the ICS forms and similar) inside the installer. Every domain's documents go into a catalog-only `ai.actionstations.<domain>-library` pack that is never bundled. The repository commits the core documents under `packs/documents/core/` and nothing of the libraries.

| Manifest field                  | Rules                                                                                                                                                                                                                                                                                                                                                                      |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `libraries.<pack>`              | `name`, `summary`, `domain` (profile id), `version`: bump the version whenever the library's documents change                                                                                                                                                                                                                                                              |
| `documents[].pack`              | `core` or `<domain>-library`; `alsoIn` lists other libraries that carry it too (each library installs on its own)                                                                                                                                                                                                                                                          |
| `slug`, `file`                  | document id (`documents/<slug>/` in the pack); `file` is `<slug>.<ext>`, ext `pdf`, `docx`, `pptx`, `xlsx`, `md`, `txt` or `zip`                                                                                                                                                                                                                                           |
| `title`, `publisher`, `edition` | as the document states them                                                                                                                                                                                                                                                                                                                                                |
| `url`, `mirrors`, `landing`     | the source file, fallbacks tried in order (Wayback `id_` captures, agency mirrors), and the page that lists it                                                                                                                                                                                                                                                             |
| `sha256`, `size`, `pinned`      | the pinned bytes and the date they were pinned; `null` until first pinned                                                                                                                                                                                                                                                                                                  |
| `license`, `basis`              | `LicenseRef-US-Government-Work` or `CC0-1.0`; a library document may also be `LicenseRef-Publisher-Terms` (its publisher's own terms). `basis` states the publisher and what the document says about its rights                                                                                                                                                            |
| `supply`, `getIt`               | `supply` is `bundled` (default, the file goes in the pack) or `user`: the library lists the document by `sha256` and `size` only, for a document whose publisher's terms do not allow passing it on. A `user` entry needs `getIt` (plain text: where to go, what to accept, which file to download), `landing` and a pinned hash, cannot be in `core` and has no `process` |
| `process`                       | `strip-cover`: a CISA CTEP `.docx` whose cover photo (unknown provenance) becomes a blank image; `extract`: a `.zip`, see below                                                                                                                                                                                                                                            |
| `links[]`                       | references a pack README names with a link but does not carry: `pack`, `title`, `publisher`, `url`, `reason`                                                                                                                                                                                                                                                               |

**Fetch.** `node scripts/fetch-documents.mjs` downloads every document into the gitignored `.cache/documents/<slug>/<file>`. It sends browser-like headers and `Range: bytes=0-` (fema.gov serves a stub otherwise), retries 429 and 5xx, rejects an HTML page served in place of the file, and refuses any file whose sha256 differs from the manifest: nothing is written. A source that serves different bytes moves on to the mirrors, so a Wayback `id_` capture taken when the file was pinned still supplies it after the publisher re-renders the file (govinfo.gov regenerates CFR PDFs every few weeks with the same text); the mismatch is reported only when no mirror has the pinned file. Give a re-pinned file a fresh capture as its mirror (Save Page Now), except where the publisher blocks the archive (ffiec.gov). It prints each document it could not get with its URL and target path, and writes `.cache/documents/fetch-report.json`. Download those in a browser (ffiec.gov serves a CAPTCHA to scripts) and save them at the target path, or drop them in `.cache/documents/inbox/` under any name; the next run moves a file whose sha256 matches into place. `--pin` records the hash of documents that have none yet. When a source publishes a new edition, the mismatch report names the new hash: check the file, then `--pin --repin <slug>` accepts it and bump the library's `version`. A file already in the cache is what `--repin` pins, so delete the cached copy first to pin a fresh download. `--only <slug,…>` limits a run, `--offline` uses only the cache and the inbox. A `supply: "user"` document is never downloaded: it is reported `cached` or `inbox` when a maintainer has put the file there (to check the pinned hash, or to `--repin` a new edition), and otherwise `user`, which never fails the run. sec.gov asks scripts to declare a contact: the fetcher sends help@actionstations.ai, or `DOCUMENTS_CONTACT=<email>` if set. dfs.ny.gov refuses the browser-like User-Agent and gets the app's own (`AS/<version> (+https://actionstations.ai)`). Some publishers refuse scripts whatever the headers: nena.org, ithandbook.ffiec.gov and fbi.gov show a Cloudflare check, apta.com answers 403, ahrq.gov's CDN refuses some networks, and osp.od.nih.gov refuses Node's requests. Their files come from the mirrors where there is a capture, or from a browser into the inbox. A Chrome started by hand (not through an automation flag) passes the Cloudflare check. Pin mirrors to the exact capture (`/web/<14-digit timestamp>id_/`): a year-only timestamp redirects to the nearest capture, which can be a different file, and the redirect counts against the archive's rate limit.

**Build.** `node scripts/build-library-packs.mjs` builds one `ai.actionstations.<domain>-library-<version>.aspack` per library into `out/library-packs/`, with `catalog-entries.json` (base URL `https://actionstations.ai/packs/files`, `--url` to change; `updated` is the newest `pinned` date) for the site's catalog. Each cached file is checked against its pinned sha256 first. The archive uses the export path's deterministic zip and is validated with `readPack` before it is written, so the same cache always gives the same archive sha256. A pinned document missing from the cache fails the build; `--allow-missing` builds without it and lists it in the README as a link. `--only <pack,…>` limits the build. Each pack's `README.md` lists every document with publisher, edition and source URL, the cover photos that were blanked, the archive members left out, the documents to add your own copy of, and the link-only references. A `supply: "user"` document is never put in the archive, even when it is in the cache: it goes in `pack.json` `userDocuments[]` (path, title, `source` = `<publisher>, <landing>`, license, description, `landing`, `getIt`, `sha256`, `size`) and is left out of `contents`, `files` and the pack license.

`node scripts/build-library-packs.mjs --core` writes the core documents to `packs/documents/core/<slug>/` and rewrites the core entry's `documents[]` in `packs/bundled.json` from the manifest; `pnpm build:packs` then enforces the 60 MB installer budget as for any bundled document.

**Archives.** `extract` packs the members in a pack format (`.pdf`, `.docx`, `.pptx`, `.xlsx`, `.md`, `.txt`) under flattened, pack-safe names. Legacy `.doc`, `.xls` and `.ppt` members are left out and listed: they are converted only where a faithful conversion is available, which this build does not have (the HSEEP MSEL template is an `.xls` and stays a link to the ZIP).
