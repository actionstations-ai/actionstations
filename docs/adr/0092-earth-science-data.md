# ADR-0092: Earth science data: replay connectors, scenarios and simulated events

Date: 2026-11-05 · Status: Accepted · Issues: #675, #676 · Spec: [0450](../specs/0450-earth-sciences.md) · Related: ADR-0076 (case data), ADR-0075 (figures)

## Context

The earth science toolkits replay real past events from free public services and simulate fictional ones. The services have terms of their own (download limits, citation), some formats are binary (miniSEED), and USGS also publishes scenario earthquakes that are neither real nor generated by the app.

## Decision

- **Nine connectors, one per source,** in `src/main/toolkits/connectors/geo/`: `comcat` (catalog, ShakeMap grid and contours, community intensity, PAGER), `scenario-shakemaps`, `fdsn-waveforms`, `volcano-notices`, `tsunami-events`, `coops-tides`, `ndbc-dart`, `quaternary-faults`, `landslide-assessments`. Hosts are fixed in code; every user-supplied code or id is checked against a fixed shape before it reaches an address. Registration is `registerGeoscienceToolkits` at startup.
- **ComCat reuses the hazard-data catalog address** (`USGS_EVENT_QUERY` in `hazards/sources/usgs.ts`), so the catalog is queried one way everywhere.
- **Waveforms are miniSEED, decoded in the app** (`miniseed.ts`: Steim-1 and Steim-2, integer and float records, both byte orders). Each Steim record is checked against its reverse integration constant, so a wrong decode fails a test instead of drawing a wrong seismogram. At most three requests are in flight at once (the data centers' stated limit), a window is at most 30 minutes, at most six stations, and every dataset cites its network and data center.
- **Grids ride in GeoJSON.** The ShakeMap grid is one feature whose `grid` property holds the intensity values (north row first, block-averaged to at most 100 columns and marked modified), so case data resolves it like any features dataset and the `shakemap_intensity` figure reads it directly.
- **A scenario is not a historical event.** The case-data provenance has two origins. A fetched scenario is stored as `historical` (it is a published USGS product with a retrieval date), but its source line, every dataset label and its citation say "scenario, not a real earthquake", and its connector ignores the period because the scenario catalog has no real dates.
- **The volcano notice archive is reachable by GET only for the past year** (VONAs). Older notices need a search request the connector layer does not make; the user pastes them in by hand.
- **Shapefile-only products are linked, not parsed.** Post-fire hazard polygons are shapefiles on ScienceBase; the connector brings the summary, the median rainfall thresholds (a small CSV) and the item address.
- **Simulated events use simple published relations** (see `toolkits/geo/simulate`): a ground-motion relation for intensity, an Omori-Utsu aftershock sequence matched to its forecast, a unrest sequence, arrival times from distance and speed, and debris flows from a rainfall scenario. All are labeled simulated by the framework.
- **Timing measures read simulated events through the same files.** The case-data pipeline checks a `reports` dataset as text entries (`t`, `title`, `text`), so ground-truth events and modeled series are written as such entries that also carry the keys the metric readers want (an event's `id`, `time`, `kind`, `area`, `attrs`; a series' `zone`, `quantity`, `points`); the extra keys stay in the file. The simulated earthquake, tsunami, lahar, unrest and debris-flow generators write `sim-*-events` and `sim-*-series` datasets, and each toolkit names them as the `groundTruth` and `series` of its measures; a test checks the names against what the generators produce.

## Consequences

- A connector change is a fixture change: each connector's tests run on recorded responses; live checks run only with `LIVE=1`.
- Adding a data center means adding a host to `FDSN_CENTERS`; nothing a user types can add one.
- If the case data model gains a scenario origin, `scenario-shakemaps` is the one connector to move to it.
