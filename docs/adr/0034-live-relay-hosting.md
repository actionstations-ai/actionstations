# ADR-0034: Live play relay: one server core, Cloudflare free plan, hand deploy

Date: 2026-10-29 · Status: Accepted · Issues: #408 (#409 adds the self-hosted adapter) · Specs: [0408](../specs/0408-live-relay-cloudflare.md), [0409](../specs/0409-live-self-hosted-server.md) · Related: [ADR-0027](0027-live-play-protocol.md), [ADR-0032](0032-lan-session-server.md), [ADR-0023](0023-free-github-actions.md)

## Context

Remote and hybrid exercises need a meeting point on the internet; organizations without internet need the same thing on their own network; and the in-app server for the room's Wi-Fi (#407) implements the same contract. The protocol (ADR-0027) already makes every server blind to content. What remained to decide: how three servers stay one behaviour, what the public relay runs on without ever costing money (CONTRIBUTING, Project rules 1), how it is deployed without a secret in GitHub, and how one anonymous person is kept from spending the shared free allowance (the security review of the first pull request).

## Decision

- **One server core.** `SessionHub` in `src/shared/live/hub.ts` (ADR-0032) is the only implementation of the server contract. It gained what servers that persist or hibernate need: a pluggable `HubStore` (`MemoryHubStore` by default; SQLite in a Durable Object for the relay; `node:sqlite` for the self-hosted server), `restore()` to re-register sockets after a hibernation, budgets for every sender, byte-limited catch-up pages, and send-error surfacing. The relay packages under `relay/` are adapters, wrangler configuration, packaging and docs: `relay/core` holds only what two adapters share and the hub does not (the HTTP shapes, the connection contract, tokens, edge rate windows).
- **The contract is a test suite.** `src/shared/live/server-conformance.ts` runs against `MemoryServer`, the LAN server over WebSocket and SSE, and the relay's Durable Object; `hub-store-conformance.ts` runs against every store. A server or store is conformant when the suites pass.
- **Budgets for every sender.** Stored-envelope, stored-byte and lifetime row-write caps apply to controllers too: past them a participant's frame is refused with `STORE_FULL`, a controller's is still routed live (an end must get through) but not stored, and the controller is told. A sender's `seq` is recorded only after a frame passed every check, so refused frames cost nothing. Catch-up is one page per request, cut by entries and by bytes (512 KiB), and the client continues from `to`.
- **The connection contract keeps tokens out of URLs.** `GET /v1/sessions/<id>/ws?client=<id>` with subprotocols `as-live.v1`, `j.<joinToken>`, `r.<resumeToken>` (the server echoes `as-live.v1`); controllers send `Authorization: Bearer`; SSE and POST (self-hosted and LAN) carry `X-AS-Join` / `X-AS-Resume`. Any token in a query string is refused, so request logs and `wrangler tail` never see one.
- **The public relay runs on Cloudflare's free Workers plan on an account with no payment method.** One Durable Object per session (SQLite backend, hibernation API, alarms for 72-hour retention and the one-hour tombstone), a quota object counting sessions per UTC day for the account (25) and per address (3, IPv6 by /64), and a mapping of the runtime's documented limit errors to `503 DAILY_LIMIT`. Session creation must be JSON without an `Origin` header (a browser always sends one; the desktop app never does), so a web page cannot spend the quota. A Turnstile challenge was considered and not adopted: the controller is a desktop app, not a browser, and the per-address and per-day caps with no payment method bound the harm; revisit if the metrics show abuse. The per-session caps (1,500 stored frames, 12 MiB, 3,600 row writes, 30 frames a minute per participant) keep the worst day at 25 × 3,600 = 90,000 row writes, under the plan's 100,000.
- **Deployed by hand, never by a workflow.** `wrangler` runs through `pnpm dlx` at a pinned version from a developer's machine after a browser login, with telemetry off; it is not a dependency, and no Cloudflare token exists in GitHub. `wrangler.toml` holds names and bindings only.
- **The server stores no session name.** `POST /v1/sessions` takes the protocol version and, optionally, the join-token hash; the app sets the hash with `POST …/join-token` right after creation, since the join token derives from the session id the server mints.

## Consequences

- Any server operator, the project included, sees ids, sizes, timing and addresses and nothing else; the relay's README states it and the deploy guide repeats it.
- The relay cannot incur a charge: no payment method, free products only, every limit fails closed, and one person cannot take more than three sessions of the day's 25. A very busy day ends at 25 sessions until 00:00 UTC, and the app must say so plainly (#410).
- The LAN server (#407) and the relay share every behaviour change through one file; the self-hosted server (#409) is one more adapter and one more store.
- The Cloudflare adapter is tested under a small runtime shim (`SqlStorage` on `node:sqlite`, fake hibernatable sockets) inside the root Vitest run, because `@cloudflare/vitest-pool-workers` pins vitest 4 and the repository is on 5. A run under `wrangler dev` or workerd is a follow-up before the first deploy; the Worker bundle is checked with `wrangler deploy --dry-run`.
- `@cloudflare/workers-types` is not used: it replaces the DOM globals the shared protocol code compiles against. The adapter declares the slice of the runtime it uses in `src/workers-runtime.d.ts`.
