# ADR-0012: Inject stages — template-schema-guided text, deterministic media plan, keep-with-warning

Date: 2026-10-21 · Status: Accepted · Issue: #34

## Context

The MSEL gives each row a format (taxonomy type) and a one-paragraph event. Turning rows into deck pages needs (a) fields that fit a template's JSON Schema exactly (`additionalProperties: false`), (b) identifiers that stay consistent across 25 pages written in separate model calls, and (c) a media plan that respects [CONTRIBUTING.md, Project rules 5](../../CONTRIBUTING.md#project-rules) (text-bearing media is template-rendered; AI pixels only for photographic content). Local 30B models fill schemas well when shown the schema, but still drift on field names and invent second hostnames when they cannot see what earlier pages said.

## Decision

- **Type choice is deterministic.** STARTEX / TIME_JUMP / ENDEX rows become control cards. Other rows keep `row.format` when a template is installed; otherwise the first installed type along a fixed fallback chain (`TYPE_FALLBACKS`, by category) is used and reported as `INJECT_TYPE_FALLBACK`; when nothing in the chain is installed the taxonomy type is kept with no template (`INJECT_TEMPLATE_MISSING`) and the model fills the taxonomy's key fields. The model may only switch type to another installed template.
- **The prompt carries the template schema** (one line per field: type, required, description, example) plus a "facts so far" list (hosts, IPs, flights, tickets, places, handles, files, people) extracted from every earlier row and inject, and the story so far. Fields are validated with the template's schema; the ajv issues go back once in a repair call. A page that still fails is **kept with `INJECT_FIELDS_INVALID`** rather than failing the job: a page the user can fix in the editor beats a failed 25-page run. render:inject refuses invalid fields, so the warning is also what the user sees before rendering.
- **Render paths are planned in code, not by the model** (`planMedia`): template when installed; `ai_image` when the taxonomy allows it and the type is photographic (scene/CCTV/signage) or the template has an image slot and the row or the inject's `*Brief` field asks for a photo; `tts` for voice types with post-FX fixed per type (radio / phone / pa+terminal_ambience); `ai_video` only when the row asks for footage. The model is called only when there is a prompt or voice line to write, and its reply is normalised onto the plan (positive-only image prompt — SDXL ignores negation — plus a standard negative prompt; voice lines fall back to the transcript fields).
- **Media job order per inject:** AI image → template (composite via the `<slot>-<ULID>` asset-id convention of render/inject.ts) → TTS (+ post-FX from `providers/media/audio-fx` when present, picked up by a build-time glob) → video. A failed step is recorded (`media_render` StageRun error text, `INJECT_MEDIA_FAILED` warning) and the next step still runs; re-rendering a path replaces only that path's assets.
- **One generation job per scenario** (`CONFLICT` otherwise). `generate:injects` without row ids fills gaps (rows without a finished inject); explicit row ids regenerate and push an `ai` version. Per-inject StageRuns (`inject_text`, `inject_media_brief`, `media_render`, keyed by inject id) live in `scenario.provenance` beside the pipeline's runs.

## Amendment (0.1.1: #166, #175, #177)

- **Deterministic field repair** (`src/main/generate/injects/repair.ts`). Keys an `additionalProperties: false` object does not declare are dropped on every draft, nested objects included. Enum values outside the allowed set (a case-insensitive match, else the schema `default`, else the first value), strings over `maxLength` and strings a simple character-class `pattern` rejects (a 19-character tweet handle) are fixed in code only after the model's repair round leaves them wrong, because the model maps "Urgent" to "Critical" better than code does. Every value repair is an `INJECT_FIELDS_REPAIRED` warning on the inject. The media job applies the same repair before the template step, so injects stored before this change render too.
- **Render failures name the fields.** The media job validates the fields before the template step; what still fails is an `INJECT_RENDER_INVALID` warning on the inject listing each field (shown in the inject editor with its suggestion, cleared when a save makes the fields valid). Other step failures stay `INJECT_MEDIA_FAILED`. A generated still is kept as a `generated` asset when the template or composite step fails, and the job log has one line per inject naming what rendered and which step failed.
- **Variants.** `InjectTextOutput.variant` (optional) is checked against the template's `meta.variants`; an unknown value falls back to the regenerated inject's variant, else the template default, and is logged. render/inject.ts uses the saved variant.
- **Scene anchor after the scene.** `anchoredPrompt` puts the camera-style anchor first, then the model's prompt; the profile's setting anchor follows as `Setting: …` guidance, and is the scene only when the prompt has no scene of its own (only camera, framing and light words).
- **Every skipped or failed row is recorded (#166).** A reply that fails the output schema after the stage's repair round gets one fresh call. A control row (STARTEX / TIME JUMP / ENDEX) that still fails gets a card built from the row (`INJECT_TEXT_FALLBACK` warning, the failed `inject_text` run kept under the inject id so the next gap-filling run regenerates it). Any other failed row gets an `inject_text` run with status `error` keyed by the row id (before, a model failure was keyed by an inject id that was never saved) and an `INJECT_TEXT_FAILED` row warning; a locked row gets a `skipped` run. Both go when the row gets its inject. A failed media brief no longer discards the inject text: the inject is saved without a brief and the media job writes one.

## Consequences

- Inject quality depends on template schemas carrying good descriptions and examples; templates are the prompt.
- A regenerate run for the whole MSEL costs one text call per row plus one brief call per non-template-only inject (roughly a third of rows for Scenario 3).
- The facts extractor is regex-based (deterministic, no model call); unusual identifier schemes may be missed and must then be caught by the critique stage or the user.
- The ComfyUI adapter and audio-FX chain ship from #32; until merged, image/video steps report "no adapter" and TTS post-FX is logged as skipped.
